# AGENTS.md — documentation

This file covers the documentation site in `docs/`. Read the root
[`AGENTS.md`](../AGENTS.md) first: the Git, licensing and repository-wide rules
there apply here and are not repeated.

## What this product is

A static documentation site for Kiboar: the official KiCad library and how to
use it, Kiboar Studio and the licences. It covers both paths, buying an
assembled keyboard or building your own. Built with Astro 7 and Fumadocs. English
is served at `/docs` and Spanish at `/es/docs`. It is the `kiboar-docs` package
in the root pnpm workspace and deploys to Vercel from the `docs` Root Directory.

## Layout

- `content/docs/` — the pages.
  - `index.mdx`, `index.es.mdx` — home pages; the family block between the
    generated markers is generated.
  - `install/`, `contributing`, `licensing` — hand-written, English and Spanish.
  - `libraries/` — generated by `library/tools/gen_docs.py`; do not edit it by hand.
- `src/` — components, layouts, the docs route, i18n, search and the STEP
  viewer.
- `public/footprints/` — generated SVG previews, committed.
- `vercel.json` — build command and output directory for the deployment.
- `astro.config.mjs`, `tsconfig.json`, `package.json` — site configuration.

## Rules

- **Generated pages are regenerated, not edited.** `content/docs/libraries/` and
  the blocks between the generated markers come from `library/tools/gen_docs.py`. Change
  the library or the generator and re-run it.
- **Generated previews are regenerated, not hand-drawn.** `public/footprints/`
  comes from the KiCad SVG export loop documented in `docs/README.md`.
- **Every page exists in English and Spanish.** Update both locales when a page
  changes.
- **No `base` path.** The routes are `/docs` and `/es/docs`; do not add a base
  path or a server adapter. The output is static.
- **Vercel builds from the workspace root.** The project Root Directory is
  `docs`; the build command is
  `cd .. && pnpm turbo run build --filter=kiboar-docs`. Do not hard-code an npm
  command or a second lockfile.
- **The deployment owns `/docs` and `/es/docs`.** The root of the domain is
  `web` and `/shop` is the Medusa store; the docs project must not claim `/`.
- **The library lives in `library/`.** The generator reads `library/footprints/`;
  do not copy or relocate library data into `docs/`.
- `docs/dist/` and `docs/.astro/` are generated; do not commit them.
- Keep component documentation factual: behaviour, pinouts and limitations come
  from the datasheet and the CAD files, not from guesses.

## Commands

From the repository root:

```bash
pnpm install
pnpm --filter kiboar-docs dev
pnpm lint:docs
pnpm turbo run typecheck build --filter=kiboar-docs
python3 library/tools/gen_docs.py --check
```

## Before a PR

- `pnpm lint:docs` passes.
- `python3 library/tools/gen_docs.py --check` passes.
- `pnpm turbo run typecheck build --filter=kiboar-docs` passes.
- `docs/dist/docs/index.html` exists.
- Both locales were updated where the page changed.
- Relative links resolve.
- Paste the real command output in the pull request.

## Labels

| Label | When |
| --- | --- |
| `product:docs` | Every issue or pull request that touches `docs/` |
| Exactly one `type:*` from [`../LABELS.md`](../LABELS.md) | Matches the title prefix; usual here: `docs`, `feat`, `fix`, `refactor`, `chore`, `test`, `build` |
| `risk:consequential` | A deployment, route or content-contract change that affects the public site |

If the change also touches the library, Studio or root CI, add that product's
label too. The full policy is [`../LABELS.md`](../LABELS.md). Do not use
`area:*` for new work.

## Git

Follow the root `AGENTS.md`: issue → branch → pull request. Use
`docs/<issue>-<slug>` for a documentation change and a Conventional Commit with
the same prefix. Do not commit `docs/dist/`.
