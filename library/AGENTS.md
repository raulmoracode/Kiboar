# AGENTS.md — KiCad library

This file covers the KiCad library in `library/`. Read the root
[`AGENTS.md`](../AGENTS.md) first: the Git, licensing and repository-wide rules
there apply here and are not repeated.

## What this product is

The official Kiboar component library in **KiCad 10**: the parts the brand's own
keyboards are designed with, published so anyone can design and build their own.
145 symbols, 173 footprints in 26 `.pretty` libraries, and 129 3D models covering
124 of the 173 footprints. Keyswitch footprints and models are being redesigned
and are not in this version. It ships as a PCM package and as a clone with
library tables.

The library is one product of the brand, not the whole repository. It must stay
useful to someone who never buys an assembled keyboard.

## Layout

- `symbols/Kiboar.kicad_sym` — the single symbol library.
- `symbols/CONTENT-REPORT.md` — datasheet status per symbol.
- `footprints/Kiboar_*.pretty/` — one library per component family.
- `3dmodels/Kiboar_*.3dshapes/` — STEP models, referenced by
  `${KIBOAR_3DMODELS}`; `3dmodels/README.md` is the generated inventory.
- `lib-table-files/` — the global library tables for a clone install.
- `pcm/metadata.json` — PCM package metadata.
- `tools/` — Python scripts (standard library, except `build_pcm.py --schema`
  needs `jsonschema` and network access); the tools have a `--check` mode,
  except `lint.py`, which runs its checks directly.

## Install contract

- For a clone install, `KIBOAR_ROOT` points at **this directory**
  (`<clone>/library`) and `KIBOAR_3DMODELS` at `$KIBOAR_ROOT/3dmodels`.
- `lib-table-files` reference `${KIBOAR_ROOT}`. Never hard-code an absolute
  path or `${KIPRJMOD}`.
- The PCM ZIP keeps `symbols/`, `footprints/` and `3dmodels/` at its internal
  root. Moving files inside `library/` must not change the archive layout.

## Hard rules

### KiCad format

The files are **KiCad 10 format**. Do not "downgrade" them to open in KiCad 8/9.
The byte check is the authority; run it from the repository root:

```bash
work=$(mktemp -d)
cp -R library/footprints "$work/"
cp library/symbols/Kiboar.kicad_sym "$work/symbols.kicad_sym"
kicad-cli sym upgrade "$work/symbols.kicad_sym"
for library in "$work"/footprints/*.pretty; do kicad-cli fp upgrade "$library"; done
diff -r library/footprints "$work/footprints"
cmp library/symbols/Kiboar.kicad_sym "$work/symbols.kicad_sym"
```

If any byte changes, the source was not current: commit the upgraded files.

### Footprints

- Every placed-part footprint needs a courtyard on its own side
  (`F.CrtYd`/`B.CrtYd`). `python3 library/tools/gen_courtyard.py` derives one
  from the Fab outline and pads plus 0.25 mm, snapped to 0.05 mm. Leave
  hand-drawn courtyards alone.
- `(attr ...)` must match the pads: `through_hole` if any pad is `thru_hole`,
  otherwise `smd`. Footprints with only `np_thru_hole` pads keep their own
  choice.
- Model paths must use
  `${KIBOAR_3DMODELS}/Kiboar_<family>.3dshapes/<name>.step`. Never use an
  absolute path, `${KIPRJMOD}` or an undefined variable.
- Model file names are case-sensitive. `SLLB510100.step` and `.STEP` are not the
  same file on Linux.

### Symbols

- Names and values contain no whitespace.
- One reference prefix per family and no `?`: `SW` for switches, buttons,
  encoders, DIP and joysticks; `U` for MCU/modules; `J` for connectors; `D` for
  LEDs; `BT` for battery holders; `DS` for displays.
- Manufacturer data lives in `Manufacturer` and `MPN` only. Do not add `MF`,
  `MP`, `MANUFACTURER`, `Manufacturer_Name` or similar.
- Keep `ki_keywords` and a `ki_fp_filters` entry that matches the linked
  footprint.
- The `Footprint` property must resolve to an existing `.kicad_mod`, exact case.

### Licensing and provenance

- `../NOTICE` is authoritative. The collection is **mixed-licence**: original
  work is MIT; ten SnapEDA symbols and five Component Search Engine symbols are
  CC BY-SA. No 3D model is third-party.
- Original models and symbols carry their authorship in the file, written by
  `library/tools/provenance.py`. Its `REWRITTEN_MODELS` and `EXTERNAL_SYMBOLS`
  are the machine-readable half of `NOTICE`: record a file there before adding
  third-party CAD, or the stamp will claim it. `REWRITTEN_MODELS` are original
  models whose header named another machine, and get their whole `FILE_NAME`
  call replaced.
- Do not relicense third-party files, do not remove or weaken `NOTICE`, and do
  not add new non-commercial content.
- New CAD data needs its origin and licence recorded in `NOTICE`, or must be
  original work.

### Generated files

- `3dmodels/README.md` contains a generated inventory between markers. Run
  `python3 library/tools/model_inventory.py --write` after adding or referencing
  models.
- `docs/content/docs/libraries/` and the family blocks of the docs home pages
  are generated by `library/tools/gen_docs.py`. Do not hand-edit them; see
  [`../docs/AGENTS.md`](../docs/AGENTS.md).
- `symbols/CONTENT-REPORT.md` is a maintained report, not a generated page;
  update it when a datasheet is verified.

## Commands

From the repository root:

```bash
python3 library/tools/lint.py                    # every rule in one place
python3 library/tools/gen_courtyard.py --check   # courtyards
python3 library/tools/normalize_symbols.py --check
python3 library/tools/model_inventory.py --check
python3 library/tools/provenance.py --check      # authorship stamps (also inside lint)
python3 library/tools/build_pcm.py --check --schema
```

## Labels

| Label | When |
| --- | --- |
| `product:library` | Every issue or pull request that touches `library/` |
| Exactly one `type:*` from [`../LABELS.md`](../LABELS.md) | Matches the title prefix; usual here: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `build`, `release` |
| `risk:consequential` | A breaking library, PCM or clone contract change |

If the change also touches root files, CI or another product, add that product's
label too. The full policy is [`../LABELS.md`](../LABELS.md). Do not use
`area:*` for new work.

## Git

Follow the root `AGENTS.md`: issue → branch → pull request. Use
`fix/<issue>-<slug>` or `feat/<issue>-<slug>` and a Conventional Commit with the
same prefix. Do not commit `dist/`.
